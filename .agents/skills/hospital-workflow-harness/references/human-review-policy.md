# Human Review Policy

Codex の出力は、業務改善や文書化のたたき台です。運用変更、配布、掲示、外部送付、システム設定変更の前に人間が確認します。

成果物を生成した時点の `run.json` は `review_pending` とします。人間が確認する前に `completed` と記録してはいけません。

## 必ず人間が確認する項目

- 院内規程との整合
- 個人情報や機密情報が含まれていないか
- 現場の実際の業務手順と合っているか
- 例外処理が漏れていないか
- 誰が実施・確認・承認するか
- システム会社や情報システム部門への確認が必要か
- 法務、契約、監査、医療安全に関わる論点がないか

## Codex が断定しない項目

- 法令適合性
- 医療安全上の妥当性
- ベンダー製品の実装可否
- 既存システムの内部仕様
- 費用、工期、契約条件
- 外部サービスや既存システム設定の実装可否

## 確認先の例

| 論点 | 確認先 |
| --- | --- |
| 個人情報、機密情報 | 情報システム、個人情報保護担当 |
| 契約、外部委託 | 総務、法務、購買 |
| システム連携 | 情報システム、既存ベンダー |
| 業務手順変更 | 部門管理者、現場責任者 |
| 医療安全との境界 | 医療安全管理部門 |

## 出力末尾に入れる確認欄

重要な成果物には、末尾に以下を付けます。

```markdown
## 人間が確認すべき点

- [ ] 患者情報・個人情報が含まれていない
- [ ] 院内規程と矛盾していない
- [ ] 現場の実際の運用と合っている
- [ ] 例外処理が確認されている
- [ ] 必要に応じて情報システム・法務・ベンダーへ確認した
```
