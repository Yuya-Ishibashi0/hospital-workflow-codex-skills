# Output Contracts

Codex の成果物は、できるだけ同じ構造で出します。これにより、レビュー、修正、院内共有がしやすくなります。

## Artifact-first rule

成果物は原則としてファイルで作成します。チャット欄には、成果物の本文全体を貼り付けません。

- 文書、報告書、依頼文、マニュアル、議事録: `.docx` または `.md`
- 表、対応表、チェックリスト、アンケート集計: `.xlsx` または `.csv`
- 研修資料、掲示物、スライド構成: `.pptx` または `.md`
- 複数形式が必要な場合: 主要成果物を `.docx` / `.xlsx` / `.pptx`、補助資料を `.md`

チャットで返す内容は、作成したファイル名、保存場所、確認ポイント、未入力・不足情報の要約に限定します。

## 共通構成

すべての成果物に、必要に応じて以下を含めます。

- 目的
- 対象範囲
- 前提
- 現状整理
- 課題
- 改善案
- 不足情報
- 人間が確認すべき点
- 次のアクション

## 業務フロー整理

- 業務名
- 関係者
- 入力
- 作業手順
- 出力
- 例外処理
- 二重入力・転記ポイント
- 改善候補

## 既存様式への情報整理

- 元資料
- 既存様式
- 項目対応表
- 抽出した情報
- 不足情報
- 空欄として残す項目
- 転記ルール
- 人間が確認すべき項目

## 議事録・会議整理

- 会議概要
- 決定事項
- 未決事項
- 論点
- 担当者
- 期限
- 次回までのアクション

## 提案書

- 背景
- 現状課題
- 目指す状態
- 改善案
- 小さく試す範囲
- リスク
- 必要な確認
- 概算スケジュール
- 上司・関係部署への相談文

- 対象アンケート
- 回答数

- 自由記述の分類
- ポジティブな意見
- 改善要望
- 次回への示唆
- 報告書ドラフト
